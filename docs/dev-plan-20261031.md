## 轮转规则（每轮必读）

0. **环境注意**：本机 PATH 默认 `go` 为 1.18（无法解析 go.mod 的 1.26）。一律使用 `/usr/local/go1.26/bin/go`（或 `export PATH=/usr/local/go1.26/bin:$PATH`）执行 build/vet/test。
1. 开工先 `git status`：工作区脏则 `git stash push -m "auto-stash <时间戳>"`（**不丢弃**），再继续。
2. 取本文件中**第一个** `- [ ]` 条目，只做这一项，范围控制在约 10-20 分钟工作量；偏大的条目可拆**最小可用增量**先交付可提交的部分，剩余留待后续轮次（勾选时注明已完成部分）。
3. 实现 → 验证：server 改动 `go build ./...` + 受影响包 `go test`（公共包改动跑全量 `go test ./...`）；agent 改动 `go build ./... && go test ./...`；web 改动 `npm run build`。**不过不提交**。
4. 完成后勾选 `- [x]`，`git add`（含本计划文件），提交信息沿用仓库惯例：`feat(模块): 一行中文说明`。**不 push**。
5. 单条目超过 25 分钟仍卡住：标 `[!]` 写明原因；已有完整可用的部分可提交，否则回滚现场，进入下一条目留给下一轮。

## 禁止事项（红线）

- 不 `push`、不 `force`、不 `rebase`、不改写任何历史提交。
- 不新增 `go.mod` / `package.json` 第三方依赖；不升级现有依赖版本。
- 不做破坏性数据库迁移（不删表删列）；不改 casbin/JWT/登录/权限相关逻辑。
- 不删除现有功能、接口与测试。
- 每轮只做一个条目、一个 commit；不碰与本条目无关的文件。
